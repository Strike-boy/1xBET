# 🎮 UC Shop Bot

Telegram-бот на aiogram 3.x для приёма и обработки заказов на пополнение UC
в PUBG Mobile с ручной проверкой оплаты по скриншоту.

## Как это работает

1. Клиент нажимает «Пополнить UC», вводит сумму и свой ID игрока.
2. Бот показывает реквизиты для оплаты.
3. После оплаты клиент присылает скриншот — заказ уходит на проверку в админ-чат.
4. Админ подтверждает или отклоняет заказ прямо из чата кнопками «✅ Готово» / «❌ Отклонить».
5. Клиент автоматически получает уведомление о результате.

## Требования

- Python 3.10 или новее
- Telegram-аккаунт для создания бота и админ-группы

## Установка

```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

Скопируйте `.env.example` в `.env`:

```bash
cp .env.example .env
```

Дальше заполните значения — как их получить, см. ниже.

### Токен бота (BOT_TOKEN)

1. Напишите @BotFather в Telegram.
2. Отправьте `/newbot` и следуйте инструкциям.
3. Скопируйте выданный токен в `BOT_TOKEN`.

### ID админ-чата (ADMIN_CHAT_ID)

1. Создайте отдельную группу в Telegram (например, «UC Shop — заказы»).
2. Добавьте туда бота и назначьте его администратором группы (это нужно,
   чтобы бот мог редактировать свои сообщения с кнопками).
3. Отправьте в группу любое сообщение.
4. Откройте в браузере:
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
5. Найдите в ответе `"chat":{"id": -100XXXXXXXXXX, ...}` — это и есть
   `ADMIN_CHAT_ID` (число обычно отрицательное).

   Быстрый способ: временно добавьте в группу бота @getidsbot или
   @RawDataBot — он сразу пришлёт ID чата, после этого его можно удалить.

### Свой Telegram ID (для ADMIN_IDS)

1. Напишите /start боту @userinfobot.
2. Он пришлёт ваш числовой ID — впишите его в `ADMIN_IDS`
   (через запятую, если админов несколько).

## Запуск

```bash
python main.py
```

## Команды администратора (в личке с ботом)

- `/setcard 1234 5678 9012 3456` — обновить номер карты для оплаты.
- `/orders` — список заказов, ожидающих проверки.
- `/stats` — статистика по заказам.

## Структура проекта

## Небольшие дополнения сверх исходного ТЗ

- Номер карты хранится в базе, а не только в `.env` — значение из `/setcard`
  сохраняется и переживает перезапуск бота.
- Добавлена команда `/cancel` — клиент может прервать оформление заказа
  на любом шаге.
- Скриншот оплаты принимается и как фото, и как файл-изображение (документ) —
  многие отправляют так, чтобы не терять качество.
- Для отклонения заказа выбран самый простой вариант из ТЗ: без запроса
  причины у админа в отдельном состоянии — клиенту сразу пишется, что при
  необходимости он может обратиться в поддержку.

## Примечания

- Хранилище FSM — `MemoryStorage`: состояния живут в памяти процесса и
  сбрасываются при перезапуске бота. Если понадобится несколько воркеров
  или устойчивость к перезапускам — переходите на `RedisStorage`.
- `.env` не должен попадать в git — он уже добавлен в `.gitignore`.
